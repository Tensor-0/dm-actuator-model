# 怎么评估「换用真实执行器模型」的效果

| | |
|---|---|
| **日期** | 2026-09-17 |
| **问题** | 把 `<position kp=30>` 换成 `<dcmotor>` 之后，**怎么知道有没有变好？** |

---

## 一、⭐ 先分清三个不同的问题（混为一谈就答不清）

| # | 问题 | 测什么 | 需不需要重训 | 可信度 |
|---|---|---|---|---|
| **Q1** | 执行器模型**像不像真机**？ | 执行器自身的输入输出关系 | ❌ | ⭐ **最硬（有真值）** |
| **Q2** | 换模型后策略**还能不能走**？ | 同一策略在新模型下的表现 | ❌ | 中 |
| **Q3** | 用新模型**训练**是否更好？ | 训练后的策略质量 | ✅ | **最软（易被噪声骗）** |

**⇒ 必须按 Q1 → Q2 → Q3 顺序，不可跳级。**
Q1 不过的话，Q2/Q3 的结论全部无法解释 ——
你分不清"策略变差"是因为**模型错了**还是**任务真的更难**。

## 二、Q1：执行器级验证（本次已做）

**这是唯一有真值的评估** —— 我们手上有达妙官方台架曲线。

### 做法
在 MuJoCo 里复现官方台架的加载条件，逐点比对。

### 结果

| `stall_torque` | 平均误差 | 最大误差 | |
|---|---|---|---|
| **54（实测外推）** | **0.85%** | **3.28%** | ✅ |
| 40（说明书标称） | 9.94% | 17.00% | ❌ |

叠加图：`data/tau_omega_overlay.png`

### 已通过的检查

| 检查 | 结果 |
|---|---|
| 空载稳态 ω = V/K（扫 5 个电压） | **0.00%** 误差 |
| 力矩公式数值反推 `dτ/dv=K/R`、`dτ/dω=−K²/R` | ✅ |
| `position` 模式跟踪（目标 0.5 rad） | 收敛到 0.4999 |
| 负载扫描复现 τ-ω 直线（9 个负载点） | **0.00%** 误差 |
| 与官方 97 点曲线逐点比 | 平均 **0.85%** |

### ⚠️ Q1 的诚实边界

- 只回答"模型是否忠实复现官方台架数据"，**不回答**"策略会不会更好"
- 判据不该定得比 **±1~2%**（曲线自身的像素提取误差）更严 ——
  否则是在拟合提取噪声
- `stall_torque=54` 是从实测区外推来的，外推距离不短

## 三、Q2：sim2sim（未做，留档）

**用旧策略跑新模型** —— 隔离"执行器改动"这一个变量的唯一干净做法。

### ⚠️ 已发现的契约缺口（重要）

`UniLab/src/unilab/utils/sim2sim.py` 的契约校验**拦不住执行器改动**：

```python
ALLOWLIST    = ["training.sim_backend", "env.scene", ...]   # env.scene 在这里
WARNING_LIST = ["reward.scales", "env.ctrl_dt", ...]
DENYLIST     = ["env.observations", "env.actions", ...]     # 无任何 actuator 字段
```

- **actuator 定义就在 scene XML 里**，而 `env.scene` 属于 ALLOWLIST
- DENYLIST 里**没有任何与 actuator / XML 相关的字段**

**⇒ 换执行器模型时，`resolve_sim2sim_config` 不报错、不警告、静默通过。**

**应对**：自建校验 —— 比对训练时与评测时的 XML 哈希。

### Q2 需要的指标（现有脚本全都没有）

实测排查结果：**现有 14 个测量脚本，没有一个读力矩**；
`Entity` 类也**只有 `write_ctrl`，没有力矩读回**。

而执行器改动影响的**正是力矩** —— 现有指标（滑移/腾空/抬脚/episode 长度）
都是**运动学**量，对本改动不敏感。

要补的：

| 指标 | 读法 | 为什么关键 |
|---|---|---|
| **力矩饱和率** | `data.actuator_force` vs `forcerange` | 反映 τ-ω 约束是否生效 |
| **\|τ\| 分位数** | p50/p95/p99/max | 看策略是否在用超出真机能力的力矩 |
| **`(ω, τ)` 相图** | 散点叠在 τ-ω 曲线上 | ⭐ **最直观**：工作点是否在真机能力内 |
| 激活变量 | `data.act`（启用 `inductance`/`thermal` 后 `na` > 0） | 电流 / 温度 |

已实测可读：`data.actuator_force`、`data.qfrc_actuator`。

## 四、Q3：A/B 重训（未做，留档）

**只有 Q1、Q2 都过了才做。** 必须守的纪律（每条都来自踩过的坑）：

| 坑 | 规矩 |
|---|---|
| seed 未固定 | `override['seed']=0` **且** `override['events']={}` 清空 DR |
| 单 env 失真 | **必须 32 env**（单 env 的 episode 长度只有 1/3.8） |
| reset 传送污染 | done 步**整帧丢弃**（否则滑移虚高 5.5 倍） |
| 右删失 | 用**固定步数预算**，不用"凑够 N 个 episode" |
| 噪声 | **≥4 seed** 才下"显著"结论；说"无变化"也要 ≥3 seed |
| 聚合混淆 | 报数字必须注明**单腿/两腿**、**池化/逐 episode 等权** |

### 最容易被忽略的一条

**训练奖励涨了 ≠ 走得更好了。** 已有教训：某指标从 1.19→0.30，
但逐帧位移占比仍是 49%（还在蹦跳）；且该指标本身有膨胀 bug、跨 run 不可比。

⇒ 主判据用 `Episode_Reward/*` 单步归一化值，**不要用 `mean_reward`**。

## 五、⭐ 一个必须提前接受的预期

**Q3 很可能得出"没显著差别"。**

原因：
- 真机 τ-ω 约束主要体现在**高转速区**
- 而 dm10 走路是**低速**工况
- 现有 `forcerange=±28` 已经够宽，τ-ω 未必咬得住

**⇒ 执行器模型的真正价值，可能要到「上真机」时才体现，而不是在仿真指标上。**

所以 **Q1 的价值独立于 Q3**：
"模型忠实复现了真机"这件事本身就有意义，无论仿真指标变不变。
