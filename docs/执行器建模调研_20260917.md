# 执行器建模调研：有人在做吗？

| | |
|---|---|
| **日期** | 2026-09-17 |
| **问题** | 我们用到的仓库 / 开源项目 / 类似项目，**是否有人会给执行器建模**？ |
| **结论** | **有，而且有成熟的工业范式；但"给达妙这类准直驱电机建 τ-ω 模型"是空白** |

---

## 一、一句话结论

**给执行器建模这件事本身非常成熟** —— 主流的做法就一种：
在仿真器里写一个**"线性四象限 τ-ω 曲线"**的电机模型（下面详述）。
我们缺的不是方法，而是**这块电机的参数** —— 而这恰好是本次从达妙官方曲线提取出来的东西。

---

## 二、四个层次：从最主流到最专门

### 第 1 层：工业标准范式 —— Isaac Lab 的 `DCMotor`（⭐ 最该看这个）

`isaac-sim/IsaacLab` → `source/isaaclab/isaaclab/actuators/actuator_pd.py:338+`

它做的事，官方文档原话：

> "implements a saturation model defined by a **linear four quadrant DC motor torque-speed curve**"

模型式：

```
τ_max(q̇) = clip( τ_stall × (1 − q̇/q̇_max),  −∞,  τ_con )
```

需要四个参数：**空载转速 `q̇_max`、堵转扭矩 `τ_stall`、连续扭矩 `τ_con`、拐点速度 `V_c`**。

**为什么这对我们是好消息**：这正是我们从达妙曲线拟合出的形式
（`ω = −0.1186·τ + 6.402 rad/s`，**r² = 0.9916**）。
也就是说 **我们的数据可以直接填进这个工业标准模型的参数位**，不用自己发明模型。

### 第 2 层：进阶范式 —— PACE（ETH RSL，⭐751，Apache-2.0）

`leggedrobotics/pace-sim2real` —— 与已有报告引用的 arXiv 2509.06342 是同一工作，**代码开源**。

- `utils/pace_actuator.py`：**继承** Isaac Lab `DCMotor`，再加两项非理想因素
  - `encoder_bias`（编码器偏置）
  - `torques_delay_buffer`（指令延迟，按仿真步延后施加力矩）
- `scripts/pace/fit.py`：用 **CMA-ES** 拟合参数
- 关键设计思想：**不改仿真器本体，只做子类扩展**

**为什么这对我们是好消息**：我们用的 UniLab/MuJoCo 也是"框架不可改"的情况
（`unisim` 是第三方 wheel），**"只扩展、不改内核"正是可复用的策略**。

### 第 3 层：数据驱动 —— ActuatorNet 系列（有实现，但我们缺数据）

Hwangbo 2019（arXiv 1901.08652）的做法：用**神经网络**学 `τ(q, q̇, ...)`。
开源实现至少四个：

| 仓库 | 说明 |
|---|---|
| `ami-iit/isaaclab.actuatornet` | Isaac Lab 生态，Apache-2.0 |
| `ami-iit/element_sim-2-real-actuatornet` | 同上系列 |
| `derekc22/actuator-net-v2` | 明确标注复现 1901.08652 |
| `aeroman66/ActuatorNet` | 早期实现 |

**⚠️ 但都需要真机激励数据**（400 Hz 采样、上百万样本、约 4 分钟）。
我们电机在返修，暂不具备条件 —— 所以**这条线现在走不了**。

### 第 4 层：达妙专属 —— 有摩擦辨识工具（可借鉴）

`cdssywc/qt5_damiao_motor_friction_detection`（⭐30）

- Qt5 GUI，**自动辨识库仑摩擦 / 静摩擦力矩，以及 Damp / Inertia**
- 直接基于达妙 `DM_CAN` 协议，**能对接我们手上的电机**
- ⚠️ **许可：仅限非商用**（学术/科研/教学），商用需作者书面授权
  → **只借鉴方法，不要直接搬代码**

**为什么值得注意**：它做的正是我们缺的两类参数（**摩擦**和**惯量**）。
我们的仿真里 `dof_armature` 是拍的、摩擦几乎没建 —— 这个工具能补上。

## 四、技术要点：MuJoCo 原生表达不了 τ-ω 曲线

这一点决定了"怎么落地"，值得单独说。

| MuJoCo 的能力 | 能否表达 τ-ω 曲线 |
|---|---|
| `forcerange` | ❌ 只能给**常数**上限，与速度无关 |
| `dyntype="filterexact"` | ❌ 只能做一阶低通/延迟 |
| `dyntype="dcmotor"` | 🟡 有电机电气动态，但 **ctrl 语义从角度变电压**，会让现有的位置动作项失效 |
| 自定义代码 | ✅ **唯一可行** |

**结论**：τ-ω 曲线**必须在 Python 侧实现**（自己算 τ 并限幅）。

### 落地路径（本项目已探明，未实施）

最自然的挂载点，且**仓库里已有完全同构的先例**：

- 把 `<position>` 换成 `<motor>`（力矩执行器）
- 写一个 action term，在 `apply_actions` 里算：
  `τ = clip(kp·(q*−q) − kd·q̇, τ_max(q̇))` 然后 `write_ctrl`
- **可直接复刻** `src/unilab/tasks/locomotion/go2w/`：
  - `base.py:27-50` 的 `compute_go2w_motor_ctrl`（向量化算力矩）
  - `manager_terms.py:217-237` 的 `apply_actions`（写 ctrl）
- 声明 `requires_substep_state_feedback = True`，以拿到**每物理 substep** 的 q̇
  （否则只有 20 ms 控制步的常值，限制会太粗）

**⛔ 不要改** `.venv/lib/.../unisim/backend/mujoco/backend.py`：
它是 PyPI wheel（非 editable 源码），重装即失效，且 5 个 backend 共用这套契约。
