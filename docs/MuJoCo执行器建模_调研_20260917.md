## 一、⭐ MuJoCo 原生就有 `<dcmotor>`（含完整直流电机模型）

**本机实测**（UniLab `.venv` 里的 MuJoCo **3.11.0**，非文档推测）：

```python
m = mujoco.MjModel.from_xml_string(
    '<mujoco><worldbody>...<actuator>'
    '<dcmotor name="m1" joint="j" nominal="24 54 6.4017"/>'
    '</actuator></mujoco>')
# → dyntype=5 (mjDYN_DCMOTOR), gaintype=3 (mjGAIN_DCMOTOR), biastype=3 (mjBIAS_DCMOTOR)
```

`mjtype.h:249` 的枚举里写得很明白：

```c
mjDYN_DCMOTOR,   // DC motor electrical dynamics
```

### 官方文档原文（XMLreference）

> "This element creates a DC motor actuator. See the **DC motor technical note** for complete
> mathematical formulations and parameter semantics, but we include a few important notes below.
> **Note that dcmotor does not conform to the affine gain / bias structure of the general
> actuation model**"

**基本模型式**：
```
τ = (Kt / R) · (v − Ke · ω)          ← 反电动势
```

### 完整参数表（全部来自官方文档原文）

| 属性 | 定义 | 说明 |
|---|---|---|
| `nominal` | `"voltage stall_torque no_load_speed"` | ⭐ **编译器直接推出 K 和 R** |
| `motorconst` | `"Kt Ke"` (N·m/A, V·s/rad) | 二者皆正时取几何平均 `K=√(Kt·Ke)` |
| `resistance` | `R` (Ω) | 端电阻 |
| `saturation` | `"torque current current_rate"` | 连续扭矩上限；**自动设 `forcerange`** |
| `inductance` | `"L timeconst"` | 电气动态（L/R）；加一个电枢电流状态 |
| `thermal` | `"R C timeconst tempcoef reftemp ambient"` | ⭐ 热模型（K/W, J/K, s, 1/K, °C, °C） |
| `cogging` | `"amplitude poles phase"` | 齿槽转矩 `amp·sin(poles·θ+phase)` |
| `lugre` | `"stiffness damping coulomb static stribeck"` | ⭐ **LuGre 摩擦模型** |
| `input` | ⚠️ **版本相关**：3.11 为 `position`/`velocity`/`voltage`；3.12+ 改为空格分隔的 `pos vel ff` | 位置模式对应达妙的位置指令 |

官方原文对 `input` 的说明：

> "The control block is selected by `input`: any subset of `[pos, vel, ff]`, where pos and vel
> are setpoint inputs to the **on-board PID controller** and ff is a **torque feedforward** added
> to its output; the voltage input is the raw terminal voltage."

### 官方技术说明（含完整推导）

📄 <https://mujoco.readthedocs.io/en/stable/_static/dcmotor.pdf>
（"MuJoCo DC Motor Model", Google DeepMind）

其中有 τ-ω 关系图与**电流饱和后的平行四边形可行域**：

> "The quasi-static model assumes instantaneous electrical dynamics...
> `v = iR + Ke·ω` (1a), `τ = Kt·i` (1b)
> **Current Saturation**: `τ = clip( (K/R)(v − Kω), ±K·imax )`"

### `dc_actuator.py` 的核心（原文）

```python
def dc_motor_clip(effort, saturation_effort, velocity_limit, force_limit, vel):
    """Clip effort to the DC motor torque-speed curve.

    Linear torque-speed curve: full saturation_effort at zero velocity falling to
    zero at velocity_limit, further bounded by the continuous force_limit.
    """
    vel_at_effort_lim = velocity_limit * (1 + force_limit / saturation_effort)
    vel_clipped = torch.clamp(vel, min=-vel_at_effort_lim, max=vel_at_effort_lim)
    torque_speed_top = saturation_effort * (1.0 - vel_clipped / velocity_limit)
    max_effort = torch.clamp(torque_speed_top, max=force_limit)
    return torch.clamp(effort, min=min_effort, max=max_effort)
```

**⇒ 这就是我们要的模型，已经有人写好并维护着。**

### ⭐ 参数接口 —— 正好吃我们测出来的三个数

```python
@dataclass(frozen=True)
class DcMotorDatasheetParams:
    """Datasheet characterization of a DC motor."""
    nominal_voltage: float   # 额定电压 V_n [V]
    stall_torque: float      # 堵转扭矩 tau_stall [N*m]
    no_load_speed: float     # 空载转速 omega_no_load [rad/s]
```

**这三个数我们全有**（见 `params/dm_j4340_2ec.yaml`）。

### `BuiltinDcMotorActuatorCfg` 文档里的两个关键提示（原文）

> "Native MuJoCo `<dcmotor>` wrapper. Models a DC motor: torque is derived from voltage via
> the motor constant K and back-EMF, `tau = K * (V - K * omega) / R`.
> **The back-EMF term lives in biasprm, so MuJoCo's implicit / implicitfast integrators pick up
> its velocity derivative as effective damping.**"

> ⚠️ "`dr.pd_gains` randomizes only kp and kd; **for DR over the extensions, write directly to
> `actuator_gainprm` or `actuator_dynprm`**"

### 学习型执行器（原文）

```python
class LearnedMlpActuatorCfg(DcMotorActuatorCfg):
    """Configuration for MLP-based learned actuator model.

    This actuator learns the mapping from joint commands and state history to
    actual torque output... The network is trained offline using data from the
    real system and loaded as a TorchScript file. The model uses a sliding window
    of historical joint position errors and velocities as inputs.
    """
```

**⇒ 这就是 ActuatorNet，已在 MuJoCo 生态里实现。**

## 四、本轮实测验证（不是推测）

### 1. 参数能解析，K/R 被正确推出

```xml
<dcmotor name="m1" joint="j" nominal="24 54 6.4017" input="voltage"/>
```
```
MuJoCo 自动推出:  K = V/ω_no_load  = 3.74900
                  R = K·V/τ_stall  = 1.66622   (τ_stall=54，见下)
gainprm = [2.2494, 3.7490]   ← 即 [R, K]（数值，非公式，见下）
```

> ⚠️ `gainprm` 的**语义不必猜**——直接数值反推力矩公式更可靠（见 1b）。
> 我一开始按"通用 actuator 的 gainprm 含义"去套，得出 ❌，是错的。

### 1b. 力矩公式：数值反推（不靠猜）

固定 `qpos=0`，扫 `ctrl`(电压) 与 `qvel`，读 `actuator_force`：

| 导数 | 实测 | 理论 | |
|---|---|---|---|
| `dτ/dv` | 1.66667 | `K/R = 1.66667` | ✅ |
| `dτ/dω` | −6.24834 | `−K²/R = −6.24834` | ✅ |

**⇒ `τ = (K/R)·v − (K²/R)·ω`**，正是官方技术说明里的 `τ = (Kt/R)(v − Ke·ω)`。

### 2. τ-ω 端点与我们的曲线实测一致

```
τ = 0  →  ω = 6.4017 rad/s   ✅ 与曲线外推的 no_load_speed 相同
ω = 0  →  τ = 40.0   N·m     ✅ 即 nominal 里的 stall_torque
```

### 3. 扫电压实测：物理正确，误差 0.00%

（`integrator="implicitfast"`，空载跑到稳态）

| 电压 V | 稳态 ω 实测 | 理论 V/K | 误差 |
|---|---|---|---|
| 24.0 | 6.4017 | 6.4017 | −0.00% |
| 18.0 | 4.8013 | 4.8013 | 0.00% |
| 12.0 | 3.2008 | 3.2008 | −0.00% |
| 6.0 | 1.6004 | 1.6004 | 0.00% |
| 3.0 | 0.8002 | 0.8002 | −0.00% |

**⇒ 反电动势行为正确**：电压越低转速越低，稳态转速 = V/K。

## 四点五、⭐ Q1 执行器级验证结果（模型 vs 官方台架）

用 `tools/verify_dcmotor_loaded.py` 把 MuJoCo 的 (ω,τ) 与官方 97 点曲线逐点比：

| `stall_torque` | 平均误差 | 最大误差 | |
|---|---|---|---|
| **54（实测外推）** | **0.85%** | **3.28%** | ✅ 落在曲线自身像素噪声（±1~2%）内 |
| 40（说明书标称） | 9.94% | 17.00% | ❌ |

**⇒ 参数取 54。** 这个取舍由实测决定，不是偏好。

叠加图见 `data/tau_omega_overlay.png`（`tools/plot_tau_omega.py` 生成）。

**⚠️ 一个诚实的边界**：54 是从实测区间（3.6~19.35 N·m）**线性外推**到 ω=0 得到的，
外推距离不短。但它是**与数据自洽的唯一选择** —— 用 40 会让整条线在每个点都偏。

## 五、结论

> **"没有人用带真实执行器参数的执行器在 MuJoCo 仿真吗？"**

**有。分层看：**

| 层次 | 存在？ | 证据 |
|---|---|---|
| MuJoCo 原生支持真实电机模型 | ✅ | `<dcmotor>` 元素 |
| 有封装好的库 | ✅ | `mujocolab/mjlab`（⭐3084, Apache-2.0） |
| 有人填真实参数 | ✅ | `DcMotorDatasheetParams(V_n, τ_stall, ω_no_load)` |
| 有人做执行器学习/辨识 | ✅ | `LearnedMlpActuator`（ActuatorNet） |
| **达妙电机的参数** | ❌ **空白** | 无开源项目发布 → 本仓库补上 |

**⇒ 落地路径比我上一轮说的简单得多**：
不需要自己写 action term，**直接在 MJCF 里把 `<position>` 换成 `<dcmotor>`，
填三个数即可**。

## 六、对我们的实际影响

### 改动量对比

| | 我上一轮说的 | 实际 |
|---|---|---|
| 改 `<position>` → `<motor>` | 需要 | 仍是需要 |
| **自己写 Python action term 算 τ** | **说需要** | ❌ **不需要** |
| 声明 `requires_substep_state_feedback` | 说需要 | ❌ 不需要 |
| 复刻 go2w 范式 | 说需要 | 参考即可，非必须 |
| **实际改动** | 一大坨 | **XML 里换一个标签 + 三个数** |

### ⚠️ 但要先解决一个冲突

MuJoCo 的 `nominal="V τ_stall ω_no_load"` **由两点定义整条直线**，
所以 `stall_torque` 和 `no_load_speed` **不能独立选**。
我们的数据给了两个冲突的 stall：

| 来源 | 值 |
|---|---|
| 说明书标称 | 40 N·m |
| 曲线线性外推 | 54 N·m |

**建议取 40**（保守，不夸大高速段能力），并在参数文件注明外推值仅供参考。

### 仍需自研的部分

MuJoCo 的 `<dcmotor>` **不含**：
- 减速器（gear 由 `<actuator gear=` 单独给）
- 效率曲线（我们的 65.6% 峰值数据）
- 达妙的**具体固件行为**（12-bit 量化、Kd 范围 [0,5]）

这几项若要建模仍需自己补，但**主干（τ-ω + 反电动势）原生就有**。
